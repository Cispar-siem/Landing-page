# Reglas de OpenSpec

- Leer `../AGENTS.md` y `README.md` antes de crear o modificar una spec.
- Cada requisito debe describir comportamiento observable y una forma de validarlo.
- Usar MUST para requisitos obligatorios y SHOULD para recomendaciones.
- No agregar proveedores, precios o capacidades que no estén aprobados en `docs/DECISIONS.md`.
- Si una tarea cambia auth, billing, metering o instalación, actualizar la spec y el documento de decisión relacionado.
- No cerrar una spec por la mera existencia de código; exigir evidencia de prueba.
