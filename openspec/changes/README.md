# Cambios propuestos

Usar esta carpeta para cambios que todavía no están aprobados por la especificación vigente.

Cada propuesta debe incluir:

1. Problema de negocio o usuario.
2. Comportamiento actual.
3. Comportamiento deseado.
4. Impacto en frontend, backend, datos, billing y soporte.
5. Criterios de aceptación.
6. Riesgos y decisión requerida.

Cuando el cambio sea aceptado, actualizar `openspec/specs/cispar-agent/spec.md` y registrar la decisión en `docs/DECISIONS.md`.
